# Database Specification

## 1. ORM and Migration Approach

- **ORM**: Entity Framework Core (EF Core) with the `Npgsql.EntityFrameworkCore.PostgreSQL` provider.
- **Database**: PostgreSQL.
- **Migrations**: Code-first migrations managed by EF Core, stored in `RETAIL.BASE.DAT/Migrations/`.
- **Migration assembly**: `RETAIL.BASE.DAT` (declared explicitly in `DependencyInjectionHelper`).
- **Connection string key**: `SqlConn_RETAIL_BASE` in `appsettings.json`.
- **`OnModelCreating`**: Only calls `base.OnModelCreating(modelBuilder)` — no explicit Fluent API configuration; all schema is derived from EF Core conventions and migration scaffolding.

## 4. Implicit Join Tables (EF Core Convention)

EF Core generates these join tables from the many-to-many navigation properties. They are not explicitly declared as `DbSet` in the `DbContext` (the commented-out lines `// public DbSet<UserRole> UserRoles` and `// public DbSet<RoleMenuItem> RoleMenuItems` confirm intent to keep them implicit).

| Join Table | Left entity | Right entity |
|---|---|---|
| `RoleUser` | `Role` | `User` |
| `CompanyUser` | `Company` | `User` |
| `MenuItemRole` | `MenuItem` | `Role` |

## 5. Key Constraints Visible in Migrations

| Table | Constraint | Target |
|---|---|---|
| `Products` | `FK_Products_Brands_BrandId` | `Brands.Id` (cascade) |
| `Products` | `FK_Products_Categories_CategoryId` | `Categories.Id` (cascade) |
| `ProductPresentations` | `FK_ProductPresentations_Products_ProductId` | `Products.Id` (cascade) |

All primary keys use `IDENTITY BY DEFAULT` (PostgreSQL auto-increment sequence).
