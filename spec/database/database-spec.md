# Database Specification

## 1. ORM and Migration Approach

- **ORM**: Entity Framework Core (EF Core) with the `Microsoft.EntityFrameworkCore.Sqlite` provider.
- **Database**: SQLite (file-based; default file `retailbase.db` in the working directory).
- **Migrations**: Code-first migrations managed by EF Core, stored in `RETAIL.BASE.DAT/Migrations/`.
- **Migration assembly**: `RETAIL.BASE.DAT` (declared explicitly in `DependencyInjectionHelper`).
- **Connection string key**: `SqlConn_RETAIL_BASE` in `appsettings.json`.
- **`OnModelCreating`**: Only calls `base.OnModelCreating(modelBuilder)` — no explicit Fluent API configuration; all schema is derived from EF Core conventions and migration scaffolding.

## 7. Switching the Database Provider

Because `IRepositoryBase<>` is a technology-agnostic port (Hexagonal Architecture Phase 1), swapping the database provider requires changes in **4 places only**. No service or controller code is affected.

### Steps to switch from SQLite to PostgreSQL

**1. Replace the NuGet package in `RETAIL.BASE.DAT/RETAIL.BASE.DAT.csproj`:**

```xml
<!-- remove -->
<PackageReference Include="Microsoft.EntityFrameworkCore.Sqlite" Version="8.0.10" />
<!-- add -->
<PackageReference Include="Npgsql.EntityFrameworkCore.PostgreSQL" Version="8.0.10" />
```

**2. Update the provider call in `RETAIL.BASE.DAT/Adapters/EF/RETAIL_BASEDbContext.cs`:**

```csharp
// before
optionsBuilder.UseSqlite(connectionString);
// after
optionsBuilder.UseNpgsql(connectionString);
```

**3. Update the DI registration in `RETAIL.BASE.API/Helpers/DependencyInjectionHelper.cs`:**

```csharp
// before
options.UseSqlite(configuration.GetConnectionString("SqlConn_RETAIL_BASE"), ...)
// after
options.UseNpgsql(configuration.GetConnectionString("SqlConn_RETAIL_BASE"), ...)
```

**4. Update the connection string in `RETAIL.BASE.API/appsettings.json`:**

```json
"SqlConn_RETAIL_BASE": "Host=...;Port=5432;Database=...;Username=...;Password=..."
```

**5. Regenerate migrations** (migrations are provider-specific — SQLite uses `Sqlite:Autoincrement`; PostgreSQL uses `NpgsqlValueGenerationStrategy.IdentityByDefaultColumn`):

```bash
rm RETAIL.BASE.DAT/Migrations/*.cs
dotnet ef migrations add InitialCreate \
  --project RETAIL.BASE.DAT \
  --startup-project RETAIL.BASE.API
dotnet ef database update \
  --project RETAIL.BASE.DAT \
  --startup-project RETAIL.BASE.API
```

The same 5-step process applies in reverse (PostgreSQL → SQLite), or for any other EF Core-supported provider.
- No soft-delete triggers or database-level audit logging.
- No stored procedures or views defined in migrations.
- No explicit schema other than the default `public`.

## 8. Seed Data / Initialization Script

### Location

RETAIL.BASE.DAT.Tests/sql-scripts/sample_data_sqlite.sql
```

```
RETAIL.BASE.DAT.Tests/sql-scripts/sample_data_inserts.sql

### Prerequisites

The schema must exist before running the seed script. Apply EF Core migrations first:

```bash
dotnet ef database update \
  --project RETAIL.BASE.DAT \
  --startup-project RETAIL.BASE.API
```

### How to Apply

```bash
sqlite3 retailbase.db < RETAIL.BASE.DAT.Tests/sql-scripts/sample_data_sqlite.sql
```

### Contents

The script inserts 20 rows into each of the following tables, in dependency order:

| Table | Records | Notes |
|---|---|---|
| `Brands` | 20 | Independent; inserted first |
| `Categories` | 20 | Independent |
| `Companys` | 20 | Independent |
| `Customers` | 20 | `IdCustomerFather` set to NULL (no self-referencing hierarchy in seed) |
| `Roles` | 20 | Independent |
| `Users` | 20 | See password note below |
| `MenuItems` | 20 | `MenuItemIdFather` set to NULL (flat menu in seed) |
| `Products` | 20 | FK to `Brands` and `Categories` resolved by subquery |
| `ProductPresentations` | 20 | FK to `Products` resolved by subquery |
| `CompanyUser` | 20 | Junction: pairs Company N with User N |
| `MenuItemRole` | 20 | Junction: pairs MenuItem N with Role N |
| `RoleUser` | 20 | Junction: pairs Role N with User N |

**Total rows inserted: 240** (across 12 tables)

### SQLite-Specific Differences from the PostgreSQL Script

| PostgreSQL | SQLite (this script) |
|---|---|
| `'2023-01-01 00:00:00+00'::timestamptz` | `'2023-01-01 00:00:00'` — plain TEXT, no cast |
| `true` / `false` | `1` / `0` — SQLite has no boolean type |
| N/A | `PRAGMA foreign_keys = ON;` — must be set per connection |
| N/A | Wrapped in `BEGIN TRANSACTION; … COMMIT;` for atomic load |

### Security Note

User passwords in the seed script are plain text (`password1`, `password2`, …). The production API hashes all passwords with SHA-512 (Base64) via `CryptographerSHA512B` before storing them. **This script is for local development and test environments only — never run it against a production database.**
